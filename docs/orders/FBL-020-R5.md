  order is present below.

## Part 1 — VERBATIM order text

### Disposition and scope

```
FBL-020-R4 is REJECTED for missing mandatory runtime controls and materially false
evidence claims.

FBL-020-R5 is the only active implementation order. FBL-030 remains unauthorized.
FBL-000 and FBL-010 remain closed. Live WorkOS certification remains a separate
undischarged gate.

No product functionality, FBL-030 work, queue/outbox platform, or unrelated refactoring
is authorized.
```

### §0. Migration and delivery preflight

```
1. Repeat the persistent-environment census and return its machine-readable evidence.
   Do not attribute the result to the architect before acceptance.
2. If any persistent environment has applied any form of migration 057, freeze 057 and
   place all schema corrections in 058. Otherwise record why 057 remains safely editable.
3. In normal production mode, the migration runner must refuse further migration when an
   applied row has:
   * a NULL or unsupported checksum;
   * no corresponding migration body;
   * a checksum differing from the canonical body.
4. Any partial-chain fixture mode must be explicit and allowlisted by exact filenames and
   checksums; it must not weaken the production default.
5. Pin the retained historical fixture to fixed expected digests, not an output-only
   manifest.
6. Maintain an authoritative inventory of every 057 reconciliation. Add independent
   negative controls for the grantless-approval session revocation, supersession audit
   insertion, and request supersession.
```

### §1. Runtime identity closure

```
1. Fix cookie logout so revocation, refresh-state destruction, version advancement, and
   audit insertion commit atomically.
2. Add a full HTTP test using a callback-created, refreshable session. Logout must return
   success, clear the cookie, revoke the row, destroy all refresh state, write exactly one
   audit event, and make the original cookie unusable.
3. Make login admission and session/refresh-credential custody one atomic database
   decision. No provider network call may occur inside that database transaction.
4. Add deterministic concurrency tests proving tenant suspension, connection disablement,
   link deactivation/relinking, and effective-window closure cannot race admission and
   still create a session or store refresh state.
5. Route every callback carrying a valid sealed transaction handle through the
   server-authoritative claim/lifecycle path. Cover:
   * state, PKCE, redirect, and handle mismatch;
   * provider `error` callbacks and missing authorization code;
   * replay;
   * provider exchange and token-verification failures;
   * expiry during a slow provider exchange.
   Every real transaction must finish with one explained terminal state and one terminal
   audit event.
6. Register login-transaction and reauthentication expiry processing in the deployed
   worker alongside support expiry. Processing must be bounded, idempotent,
   concurrency-safe, and tested through the compiled worker entry point with seeded
   expired rows.
7. Make definitive refresh revocation and its audit one transaction.
8. Require access-token verification at every exported refresh/rotation boundary, or make
   unsafe lower-level primitives private.
9. Tenant-scoped MFA certification must require a currently active/effective tenant under
   the same authority rule as policy evaluation.
10. A support session whose expiry instant has passed must receive the expiry transition;
    a later human revocation must not steal or relabel that ending.
11. Attribute successful login audit evidence to the admitted tenant and user.
```

### §2. Database-reconstructable policy evidence

```
1. Version-2 PolicyDecision evidence must be relationally coherent, not merely non-null.
2. PostgreSQL must reject:
   * nonexistent or cross-tenant actors;
   * sessions, connections, subjects, or tenants that do not form the presented identity
     tuple;
   * nonexistent or mismatched role-binding authority;
   * mismatched support session/request/actor evidence.
3. Normalize array evidence where necessary so foreign keys and authorization-version
   relationships are enforceable.
4. Add direct SQL negative tests using both random nonexistent identifiers and cross-wired
   real rows.
```

### §3. Documentation and governing authority

```
1. Supply the actual management-first Version 2.0 blueprint bytes and exact checksum in
   both project copies, or withdraw every claim that the document is "in hand and
   verified."
2. Check the current R5 authority into the repository/project record so the active order
   is not dependent on an absent external document.
3. Remove all stale CI, commit, migration, worker, refresh, roadmap, and phase-state
   prose. The final report must contain one current state.
4. Replace self-referential document tests with checks against the actual supplied
   document's checksum, title, version, and governing section.
5. Give the requirement map an authoritative R5 clause inventory, unique required IDs, and
   completeness checks that fail when a requirement is omitted.
6. Reconcile README, ADR-001, AUTH-FLOWS, KNOWN-LIMITATIONS, DATA-DICTIONARY, threat
   model, module ownership, delivery report, and the project copies.
```

### §4. Verification gates

```
The existing 459-test/47-suite floor may not shrink. All failures, cancellations, skips,
and todos remain zero.

Add route-level, concurrency, database-integrity, worker-reachability,
migration-negative-control, and refreshable-logout coverage for every correction above.
Mutation-kill each newly mandatory predicate or transition.

The populated pre-057 upgrade, fresh installation, second migration run, schema
fingerprints, architecture checks, full-history secret scan, container build, dependency
audit, and evidence-artifact completeness must all remain green.
```

### §5. Delivery discipline and return packet

```
Use at most one code-bearing commit and one optional documentation-only closeout commit.
Any test, script, workflow, requirement-map executable, or source change belongs in the
code-bearing commit.

Return:

* census evidence and the 057/058 decision;
* exact commit SHAs and exact-SHA `ci.yml` runs;
* final-head artifact names, sizes, and SHA-256 digests;
* migration checksums and ledger refusal probes;

* actual governing-document filenames, hashes, titles, versions, and sections;
* an explicit statement that live WorkOS certification remains undischarged and FBL-030
  has not started.

Stop at the gate.
```

The rejection listed nine mandatory blockers against R4. They are recorded here by
severity and subject so a reviewer can map a correction to the finding it answers. The
architect's evidence citations pointed at a review workspace; the repository-relative
paths are given instead.

| Severity | Blocker                                                                      | Named evidence                                                                                                              |
| -------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Critical | Refreshable cookie logout rolls back, leaving the session live               | `apps/api/src/routes/auth.ts`, `packages/identity-access/src/session.ts`, `migrations/057_identity_boundary_completion.sql` |
| High     | Admission and credential custody are not atomic                              | `packages/identity-access/src/login-admission.ts`, `packages/identity-access/src/session.ts`                                |
| High     | Callback lifecycle claims are bypassed at the HTTP boundary                  | `apps/api/src/routes/auth.ts`                                                                                               |
| High     | Login and reauth expiry transitions are dead production code                 | `apps/worker/src/main.ts`, `packages/identity-access/src/reauthentication.ts`                                               |
| High     | Some refresh revocations and their audits are separate autocommit operations | `packages/identity-access/src/session.ts`                                                                                   |
| High     | PostgreSQL accepts fabricated or cross-wired "complete" v2 policy evidence   | `migrations/057_identity_boundary_completion.sql`, `tests/identity-evidence.test.ts`                                        |
| High     | Migration-ledger and negative-control claims are overstated                  | `scripts/migrate.ts`, `scripts/upgrade-negative-controls.ts`                                                                |
| High     | Governing-document and delivery-report truthfulness failed                   | project copies, `docs/FBL-020-DELIVERY-REPORT.md`                                                                           |
| High     | The closeout and final-head evidence violate delivery discipline             | commit `e08af427`                                                                                                           |

The rejection also recorded what it accepted, and that is not re-litigated here: the CI
evidence is genuine, both R4 runs completed four jobs successfully, the populated upgrade
fixture is genuinely nonempty, and the ten negative controls that existed at R4 execute
