## Objective

Close FBL-020 once by completing only these four outcomes.

### 1. Runtime identity and system evidence

API and worker must authenticate directly as the dedicated non-owner runtime
login.

Prove that:

* an owner or superuser cannot become acceptable through startup role
  switching;
* the ordinary runtime cannot select `actor_type='system'`;
* representative ownership, role-assumption, DDL, migration-ledger,
  trigger-control, and forged-evidence operations remain denied;
* one legitimate runtime decision produces the normalized database-owned
  evidence row.

Do not build a new identity subsystem or separate system-writer architecture.

### 2. Control-plane payload and support authority

A genuine control-plane request must reject customer resource or
organization-scope payload. It must never silently discard that payload and
return ALLOW.

Evidence writing must revalidate the exact support binding, actor, role, and
effective interval relied upon by the decision.

An unrelated surviving platform binding must not conceal the loss of the
supporting binding. Refusal must leave no policy or audit ALLOW evidence.

### 3. Approval integrity and terminal states

Approval must use the grant consumed for that request by that decider. The
grant must be valid and unexpired at consumption and approval, with coherent
decision timing.

Refuse:

* unconsumed or mismatched grants;
* expired grants;
* staged grant attachment outside the atomic approval path;
* changes from a completed state to another terminal state, including
  `approved → denied`.

Do not create a supersession workflow in this order.

### 4. Upgrade preflight and truthful refusal

Invalid retained data must fail transactionally before partial schema or data
mutation.

Use representative fixtures covering:

* retained actor mismatch;
* non-platform requester;
* non-platform session actor;
* defective approved scope;
* the migration-057 tenant mismatch.

Also prove one valid upgrade and fresh/upgraded convergence.

Refusal messages may identify bounded records and counts, but must describe
historical conflicts as hard stops requiring an approved remediation decision.
They must not claim that ordinary revocation or supersession repairs immutable
historical tuples.
