**This file exists because the R6 gate's finding C3 said it must.** R5 §3.2 required the

both are reproduced below without summary, correction or extension:

**The verbatim text of §1, §2, §3 and the rest of §4 was routed to the implementation waves
section by section and is NOT in this repository's hands.** Part 2 therefore registers those

same class of falsification the rest of this chain refuses, so none is offered: the register
records what the repository can prove it was working to, and marks the wording as derived.

This is the same defect the R5 order file carried and corrected when the text arrived. It
is recorded here as an **open item**, not as a discharged one.

## Part 3 — §4.3 addressed on its merits

§4.3 has two halves. Both are stated here with the evidence that discharges each, and with
what is **not** discharged said in the same breath.

### 3.1 The floor: at or above 577 tests / 59 suites, with zero failed, cancelled, skipped and todo

The floor is **enforced by a gate rather than reported by a sentence.**
`scripts/parse-test-summary.ts` reads all eight fields of the runner's own summary, refuses a
run that reports fewer tests or suites than its declared floors, and refuses any non-zero
`fail`, `cancelled`, `skipped` or `todo`. `.github/workflows/ci.yml` runs it on the battery
output in the step **"Enforce test summary (all eight fields, floors, zero
failed/cancelled/skipped/todo)"**, so a shrunken suite fails the job instead of passing
quietly inside a green log.

The measured battery total is **not restated here**, deliberately. It is published in
`docs/FBL-020-DELIVERY-REPORT.md` §5, where `scripts/check-published-figures.ts` reads it out
of `artifacts/test-summary.json` and fails the run if the document says anything else. A
number copied into this file would be a second, ungated publication of a figure that has
already gone stale three times in this order.

Two further readings are carried out over the same run, because a summary counter is a claim
the run makes about itself:

- **an anchored `not ok` scan** over the raw TAP, so a failing subtest inside a passing suite
  cannot be absorbed by the totals;
- **a name-set comparison between two consecutive runs**, so a suite that silently stopped
  registering tests is visible as a difference rather than as a smaller number.

### 3.3 What §4.3 does NOT discharge, said here rather than left to be inferred

**No CI run covers this working tree.** The order forbids committing, so every gate above was
executed locally against a real PostgreSQL 16 on `127.0.0.1:55434`. That is not a CI run and
is not offered as one. The single authority on which commit a run measured is
`docs/evidence/FBL-020-FINAL-STATE.json`, and `scripts/check-final-state.ts` holds every
delivery document to it.

**§4.3 is a floor, not a completion.** Satisfying it does not close §3.1, does not discharge
live WorkOS certification, and does not cure the one-commit budget violation. Those remain
recorded as blocking in the final-state record.
